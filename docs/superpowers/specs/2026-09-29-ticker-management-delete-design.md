# 标的管理与安全删除设计

## 目标

用户可以删除误录或重复的标的，但不得因删除标的而破坏已有交易历史。

## 交互

成本管理页增加“管理标的”入口。管理弹窗列出当前用户所有标的的名称、代码和类型，每项提供删除操作。用户确认后才发起删除；成功后立即刷新标的列表。

## 数据安全

`DELETE /api/tickers/[id]` 必须在服务端验证标的归属，并查询关联交易记录数量。存在任何交易记录时返回 `409`，不执行删除；只有交易数为 0 时才删除标的。这一规则不依赖前端，避免绕过界面误删。

## 范围

本次不实现标的合并、交易迁移、软删除或归档。已有交易的重复标的需先处理错误流水，再进行删除。

## 验证

测试覆盖：无交易标的允许删除；有交易标的返回冲突且不删除；界面必须二次确认；删除成功后刷新列表。

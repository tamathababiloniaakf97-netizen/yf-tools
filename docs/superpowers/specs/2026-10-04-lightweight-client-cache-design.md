# 轻量客户端缓存设计

## 目标

降低页面之间反复切换时的等待感，同时保持 Supabase 和现有 API 为唯一真实数据源，不引入本地数据库、Redis 或长期浏览器存储。

## 已确认问题

当前主要页面在组件挂载时通过 `fetch` 重新取数，离开页面后组件状态被销毁，返回时再次从空白状态开始。财务页还会先读取家庭财务、再读取投资持仓，两项独立请求串行执行。侧栏使用 `router.push` 跳转，但没有在用户准备点击时主动预取目标路由。

## 方案

在应用公共层加入 SWR 会话内存缓存。首次访问仍请求服务器；重复进入时先显示会话中已有数据，再在后台校准。缓存不写入 `localStorage`，关闭或刷新浏览器后允许重新获取，避免过期财务数据长期留存及缓存版本管理。

第一阶段只改造家庭财务页，验证模式后再逐页迁移。家庭财务数据和投资持仓分别使用稳定的缓存键，并行读取；发生新增、修改、删除或结账后，重新校准相关键。侧栏在鼠标进入可点击菜单项时调用 Next.js 路由预取。

## 数据一致性和错误处理

缓存只承担显示加速，不改变写入流程。第一次没有缓存且请求失败时显示现有错误反馈；已有缓存时保留旧数据，后台校准失败不清空界面。用户主动写入完成后触发重新获取，以服务器返回为最终结果。

## 边界

本阶段不做持久化缓存、离线模式、Service Worker、服务端数据缓存或全站一次性迁移。首次访问速度仍受接口和数据库延迟影响；目标是让重复访问立即出现已有内容，并消除可避免的串行等待。

## 验证

自动测试覆盖公共请求器的错误处理、侧栏预取触发和财务页缓存读取行为；随后运行完整测试、类型检查和生产构建。浏览器手工检查首次进入、切走返回以及写入后刷新三条路径。

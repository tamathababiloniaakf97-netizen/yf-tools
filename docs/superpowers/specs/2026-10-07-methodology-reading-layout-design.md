# 投资方法论阅读版面设计

## 目标

将投资方法论从卡片平铺改为与投资日志一致的主从阅读结构，让较长规则更容易检索、浏览和持续修订，同时保持方法论模块轻量。

## 范围

本次只调整版面与补充编辑能力，不改变 `methodology_items` 数据表，不增加迁移文件。保留现有标题、分类、规则内容、审核状态和来源字段。

明确不增加日期、标签、相互引用、富文本、版本历史和知识图谱。这些功能只有在实际使用证明有必要后再考虑。

## 页面结构

页面顶部保留“投资方法论”标题、说明文字和“添加方法”按钮。

主体采用左右两栏：

- 左栏为搜索与分类区。顶部显示关键词搜索和“全部、选股、估值、仓位、纪律、复盘”分类筛选；下方按最近更新时间排列方法列表。每项显示分类、标题和正文摘要。
- 右栏为阅读区。显示分类、审核状态、标题和完整规则内容，并提供“编辑”和“删除”操作。

桌面端左栏较窄、右栏较宽，延续投资日志的阅读节奏；窄屏下改为上下排列，避免强行压缩内容。

## 交互规则

首次进入时自动选择筛选结果中的第一条。点击左侧条目切换右侧详情；搜索或分类导致当前条目不再符合条件时，自动显示新的第一条。没有匹配结果时，左侧提示清除筛选，右侧显示空状态。

“添加方法”沿用当前弹窗。“编辑”复用同一个弹窗并预填当前内容。保存新增调用现有 POST 接口，保存编辑调用新增 PATCH 接口。删除仍需二次确认。

列表排序继续使用接口现有的 `updated_at desc`，不引入人工排序。

## 接口与数据

GET、POST 和 DELETE 的行为保持不变。在 `/api/investment/methodology/[id]` 增加 PATCH：复用现有输入校验，只更新当前用户拥有的记录，并刷新 `updated_at`。不存在或无权访问时返回 404。

前端不建立第二套方法论数据模型，也不新增客户端缓存策略；继续使用当前数据源，保存后重新加载列表。

## 错误处理

加载失败继续显示页面警告。新增或编辑校验失败时保留弹窗内容并显示错误，不关闭弹窗。删除失败时保留当前记录。接口必须按用户 ID 限定更新和删除范围。

## 验证

增加页面测试，覆盖列表与详情展示、关键词和分类筛选、打开编辑并预填内容。增加 PATCH 接口或输入处理测试，确认编辑不会绕过现有校验。最后执行相关测试、代码检查与生产构建。

# 投资决策草稿导出与复制设计

## 目标

允许已保存但未定稿的投资决策导出 PDF；已定稿决策继续保持只读，并可复制为一条新的草稿进行调整。原决策及其 PDF 不被覆盖。

## 交互

- 任何已经保存并拥有 `id` 的投资决策都显示“导出 PDF”。新建页面尚未保存时不显示，避免导出浏览器中未落库的临时内容。
- 草稿 PDF 标明“草稿”，已定稿 PDF 标明“已定稿”；空白字段和空白章节继续不输出，不要求填写完整。
- 已定稿决策页面增加“复制为新草稿”。点击后由服务器复制当前决策，成功后直接进入新草稿编辑页。
- 草稿页面不显示复制按钮，避免产生无意义的重复草稿。

## 数据与接口

- 现有 PDF 导出接口取消仅允许 `finalized` 的限制，但仍要求当前用户拥有该决策。
- 导出仍使用决策已关联的研究快照。没有研究快照时返回明确错误，因为现有决策 PDF 包含研究依据，不能伪造或自动改用最新研究。
- `DecisionReport.meta` 增加决策状态及与状态匹配的时间含义：草稿显示“最后保存时间”，定稿显示“定稿时间”。PDF 免责声明同时说明草稿内容可能继续变化。
- 新增复制接口 `POST /api/investment/decisions/[id]/copy`。接口只接受已定稿且属于当前用户的来源记录，复制可编辑字段和原研究快照，强制写入 `status: draft`，并清空新记录的 `decision_date`。
- 新草稿的 `source_type` 使用 `manual`，`source_ref` 保存来源决策 id，用于追溯但不新增数据库字段。

## 边界与错误处理

- 不修改或解锁原已定稿决策。
- 不增加版本号、差异对比、自动覆盖或数据库迁移。
- 来源不存在返回 404；来源不是已定稿状态返回 409；数据库失败返回明确错误。前端复制失败时停留在原页面并提示原因。

## 测试与验收

- 页面测试覆盖草稿显示导出按钮、已定稿显示导出与复制按钮。
- 接口/纯函数测试覆盖草稿报告状态、复制后的字段重置以及未关联快照的导出错误。
- 生成草稿和已定稿 PDF 样例，检查状态、时间标签、空字段省略、分页和中文显示。
- 运行相关 Vitest、ESLint、TypeScript 与 `git diff --check`。

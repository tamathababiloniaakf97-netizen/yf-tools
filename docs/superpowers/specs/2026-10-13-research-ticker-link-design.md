# 公司研究关联已有标的设计

## 背景

公司研究目前由用户手动输入 `asset_name`。研究档案虽然已有 `ticker_id` 字段，但新建界面没有使用它；证据等部分功能又按 `asset_name` 精确匹配，因此名称差异可能造成重复研究或资料无法汇集。

用户的固定流程是先新增标的，再建立公司研究。因此本次不支持自由输入未建档标的。

## 目标与范围

- 新建公司研究时只能选择当前用户已有的标的。
- 选择项显示“标的名称 · 代码”，便于确认准确对象。
- 创建请求同时提交标的 `id` 作为 `ticker_id`，以及标的准确 `name` 作为 `asset_name`。
- 已有关联研究的标的不再出现在可选列表中，防止重复创建。
- 没有可选标的时提示用户先到持仓添加标的。
- 不自动修改、合并或删除现有研究档案；用户后续自行处理历史名称。

## 数据流

投资研究页加载时，在现有研究与行业请求之外读取 `/api/tickers`。页面以研究档案中的 `ticker_id` 过滤已有标的，生成新建弹窗的候选项。用户选择标的 ID 后，创建逻辑从已加载列表中找到对应标的，并提交：

```json
{
  "ticker_id": "标的内部 ID",
  "asset_name": "标的准确名称"
}
```

服务端继续使用现有研究校验与 upsert 逻辑，无需数据库迁移。

## 界面与错误处理

新建弹窗使用可搜索下拉框，搜索范围包括名称和代码。候选项显示“名称 · 代码”。候选为空时展示“没有可用标的，请先到持仓添加标的”，创建按钮不能在未选择时提交。

如果标的列表加载失败，研究页面保留现有浏览和编辑能力，但新建操作显示错误，不允许退回手动名称，以免重新引入名称不一致。

## 测试

- 选择已有标的后，请求同时包含正确的 `ticker_id` 与 `asset_name`。
- 已建立研究的 `ticker_id` 不出现在候选项中。
- 未选择标的不能创建研究。
- 标的列表为空时显示先新增标的的提示。
- 现有研究加载、编辑和引用行为保持不变。

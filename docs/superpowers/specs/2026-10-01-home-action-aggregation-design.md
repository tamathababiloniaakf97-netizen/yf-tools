# 工作台行动聚合与通用计划下线设计

## 背景与问题

当前“计划管理”使用独立 `plans` 模型管理投资、年度目标和生活三个领域的计划，而投资模块已有 `investment_tasks`，年度目标和人际关系也各自保存下一步行动。这会让同一行动在业务模块和通用计划中重复建立，并产生两套状态、提醒和完成记录。

用户已确认没有需要保留的历史计划数据或计划提醒，因此不建立兼容迁移层。

## 产品定位

工作台首页是跨领域行动的聚合视图，不是行动的第二个编辑入口。

- 投资模块拥有投资待办及其状态、条件、提醒和备注。
- 年度目标模块拥有目标的 `next_action`、里程碑和进度。
- 人际关系模块拥有联系人的 `next_action` 和下次联系时间。
- 工作台首页只读取、归一化、排序和展示这些行动，用户点击后跳转到所属业务模块处理。
- 首页不提供新建通用行动、编辑领域数据、标记完成、延期或批量更新。

## 导航与路由

从侧边栏移除“计划管理”。不新增“行动中心”独立页面，因为现阶段的聚合量级不足以支撑第二个列表页。

`/plans` 页面及 `/api/plans` API 下线。项目不保留该路由的兼容重定向：导航中已无入口，且用户确认无历史数据。

## 首页行动模型

新建一个只读的统一展示类型 `DashboardAction`，它是派生视图，不是数据库实体。最少包含：

- `id`：带来源前缀的稳定展示标识。
- `source`：`investment` 、`goal` 或 `relationship`。
- `title`：用户需要处理的行动文本。
- `context`：标的、目标名或联系人姓名，用来解释行动所属上下文。
- `dueDate`：投资提醒日、目标无独立截止日时为空、人际关系使用下次联系日。
- `href`：来源模块的处理页地址。投资待办链接到 `/investment/tasks?task=<id>`，年度目标链接到 `/goals`，人际关系链接到 `/relationships`。
- `urgency`：从领域日期派生的“已过期”、“今日”、“即将到期”或“无日期”，仅用于排序和视觉提示。

聚合器为纯函数，接收投资待办、目标、联系人和当前时间，返回排序后的 `DashboardAction[]`。它只包含：

- 状态为 `pending` 或 `waiting`、并已通过审核的投资待办。
- 状态为 `active`、已通过审核且 `next_action` 非空的年度目标。
- 已通过审核且 `next_action` 非空的联系人。

排序优先级为：已过期、今日、未来有日期、无日期；同级按日期升序，日期和来源相同时使用稳定标识保持结果稳定。

## 首页界面

首页标题保留“本周工作台”，副文案调整为强调跨领域处理。移除“管理计划”按钮、`WeeklyFocus` 和原有基于 `Plan` 的四个卡片。

首页显示一个“待推进行动”列表：

- 每项显示行动标题、来源领域、上下文和日期状态。
- 每项只有“去处理”操作，使用 Next.js 导航跳转到 `href`。
- 投资、年度目标或人际关系某一数据源加载失败时，首页显示该来源的警告，但仍展示其他成功加载的行动。
- 所有数据源都无行动时，显示“暂无待推进行动”，不引导用户在首页新建。

本次不实现“本周重点”的手动勾选，因为现有领域实体没有统一的重点标记，强行加入会产生新的跨领域写入模型。

## 提醒

提醒中心不再读取 `plans`。它继续使用已有的投资待办和人际关系提醒。年度目标的 `next_action` 没有独立日期，本次不将其转换为提醒。

## 删除范围

删除通用计划的页面、组件、API 路由、校验逻辑、仪表板聚合逻辑、提醒生成逻辑和 TypeScript 类型。数据库迁移文件作为已执行过的历史记录保留，不改写旧迁移；后续可在需要整理数据库时增加新迁移删除 `plans` 表，但本次不要求对已部署环境执行破坏性 DDL。

## 测试与验收

- 导航测试证明不再出现“计划管理”和 `/plans`。
- 行动聚合器测试覆盖三个来源的归一化、状态/审核过滤、日期优先级和跳转地址。
- 首页组件测试覆盖混合行动展示、去处理链接、部分数据源失败和空状态。
- 提醒 API 测试证明不再查询通用计划，仍正常聚合投资和人际关系提醒。
- 运行定向测试、全量测试、TypeScript 检查和生产构建。

## 非本次范围

- 不新建独立行动中心路由。
- 不新建通用行动表或通用状态机。
- 不在首页标记完成、延期或编辑行动。
- 不将 `goals.next_action` 拆成独立数据库实体。
- 不执行删表或其他破坏性数据库操作。

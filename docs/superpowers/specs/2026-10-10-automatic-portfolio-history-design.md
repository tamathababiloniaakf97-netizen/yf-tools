# 自动投资组合历史绩效设计

## 目标与边界

系统每天在北京时间 08:30 由 Supabase Cron 调用 Edge Function，无论网页是否打开，都更新行情并保存投资账户快照。历史绩效从期初日期开始积累，不使用当前价格伪造过去数据。

第一版提供账户净值曲线、TWR、最大回撤和满 60 天后的年化收益率。XIRR继续沿用现有资金收益率计算。标普500基准对比纳入快照，但基准行情失败不阻止账户快照保存。

## 数据模型

扩展现有 `nav_history`，保存总资产、现金、持仓市值、当日外部净资金流、基金份额、单位净值、估值状态、失败说明、标普500价格和基准净值。`user_id + date` 保持唯一，确保定时任务重试只更新当天记录。

新增持仓快照表，按用户、日期和标的保存数量、USD价格、USD市值、价格日期和价格来源。该明细用于审计账户总资产以及未来修复错误行情，不直接展示为交易流水。

## 自动任务与行情

Edge Function使用服务端权限读取已设置期初账户的用户。每次运行先批量取得标的最新有效行情并更新 `tickers.current_price`，再计算每个用户的持仓数量、现金和总资产。

支持的股票及ETF继续使用现有腾讯行情规则，加密货币继续使用 Coinbase/CoinLore。自动任务使用最近已完成行情；某个标的请求失败时沿用数据库中最后一个有效价格，并将快照标记为 `partial`。若一个仍有持仓的标的既没有新价格也没有历史有效价格，则该用户当天快照标记为 `failed`，不写入误导性的净值。

任务日志记录成功、部分成功和失败用户数量。密钥只放在 Supabase Function Secrets 和 Cron 调用配置中，不写入仓库。

## 净值口径

期初净资产等于期初现金加期初持仓市场价值，初始单位净值为 1，初始份额等于期初净资产。

以后每天先读取上一条有效快照。当日入金减出金作为外部净资金流，按上一日净值折算新增或赎回份额；当日单位净值等于当日总资产除以调整后的份额。买卖、分红和期权现金流属于账户内部变化，不调整份额。TWR等于最新净值除以首日净值减一；最大回撤使用净值的历史滚动高点；不足 60 天不显示年化收益率。

同一天重跑时从前一日快照重新计算当天份额和净值，不在已有结果上继续累加，保证幂等。

## 页面与说明

成本记录页面的“历史绩效”区域替换为净值折线图，展示账户净值与标普500基准净值，并显示 TWR、最大回撤和年化收益率。数据不足两天时显示“历史数据正在积累”；部分估值日给出提示，但仍允许查看曲线。

页面明确说明：TWR排除入金、出金影响，用于评价投资表现；XIRR考虑资金投入时间，用于评价个人资金回报。

## 测试与交付

纯函数测试覆盖份额调整、同日重算、最大回撤、年化门槛和缺失价格判定。数据库迁移测试覆盖唯一约束、RLS、服务端快照RPC与幂等更新。API和组件测试覆盖历史数据读取、空状态、部分估值提示及图表数据。Edge Function保留可注入行情获取器的核心模块，以便在本地测试成功、失败和降级场景。

代码完成后还需要在用户的 Supabase 项目中执行迁移、部署 Edge Function、配置 Function Secret，并在 Cron 中创建北京时间 08:30 的每日任务。部署属于线上变更，执行前单独核对项目并获得确认。

# 公司研究与投资决策字段引导设计

日期：2026-10-01

## 1. 背景与目标

现有公司研究的六个核心问题已有部分 placeholder，但管理者与文化、综合判断等字段缺少持续可见的写作边界。投资决策页大部分字段只有问题标题，容易把市场预期、个人判断、估值假设、一般风险和可证伪信号混在一起。

本次目标是让每个可填写栏目都有简短、始终可见的辅助文字，明确“写什么”及最常见的偏差。引导只帮助用户建立判断，不生成答案、不评分，也不把文字长度当作研究质量。

## 2. 专业设计依据

- 指导内容不依赖 placeholder：placeholder 会在用户输入后消失，不利于填写中持续校准和填写后复核。
- 使用与字段关联的 helper text，并与校验错误分开。Ant Design 中使用 `Form.Item.extra`，保留 `help` 给校验和错误。
- 常规提示只写一句；只有抽象或容易混淆的字段才附一个短例子。
- 提示使用中性语气，不使用警告图标、高亮色块或“正确答案”式措辞。

## 3. 呈现规则

1. 字段标签保持现有层级，辅助文字显示在输入控件下方。
2. 辅助文字使用界面现有的次要文字色，字号不小于 12px，不通过降低对比度强行追求“干净”。
3. 桌面端单条提示尽量不超过两行，手机端允许自然换行。
4. 文案优先采用“写入对象和判断边界；避免常见偏差”的结构，不机械地对每个字段都输出三行模板。
5. 已填内容、草稿和已定稿决策都继续显示提示。已定稿页面虽为只读，提示仍帮助用户复核当时答案是否答非所问。
6. 必填、可选和校验规则继续由标签和错误信息表达，不把错误提示混入写作指导。

## 4. 公司研究字段文案

| 字段 | 始终可见的辅助文字 |
| --- | --- |
| 公司靠什么生意挣钱？ | 写清主要客户、交付的价值和收入来源；不必复述公司历史或产品清单。 |
| 为什么客户愿意持续付钱？ | 写客户真正购买的结果及需求持续的原因；避免只写“体验好”。 |
| 为什么竞争者难以抢走？ | 写最关键且可验证的优势及其持续机制；不罗列泛泛的公司优点。 |
| 五年后继续挣钱依赖哪些关键假设？ | 写必须持续成立的外部条件和内部能力；不确定时直接写待验证事项。 |
| 什么事实出现会证明判断错误？ | 写可观察、可证伪的反证；例：核心产品连续两个季度量价齐跌。 |
| 挣到的钱质量如何？ | 写利润能否转化为现金、维持增长需要多少投入及资本回报的持续性。 |
| 管理者与文化 | 用可验证的行为评估诚信、资本配置、激励和对小股东的态度；不以个人魅力代替证据。 |
| 当前结论 | 写基于当前证据的阶段性判断和置信边界；这里不直接写买卖决定。 |
| 主要风险 | 写可能改变长期收益或估值的具体风险及传导路径；避免只写“竞争激烈”或“宏观不好”。 |
| 仍不知道的事情 | 写当前无法回答且会影响判断的问题；后续可转为验证任务。 |
| 原投资逻辑 / 研究摘要 | 用于保留旧版内容或汇总研究主线；不要用它替代上方的结构化回答。 |

辅助检查区在折叠标题下增加一条共享说明：“状态只记录是否已考虑，不代表研究得分；备注写下结论或待验证点即可。”各检查项的问句本身作为具体引导，不重复显示六次相同的辅助文字。

## 5. 投资决策字段文案

| 字段 | 始终可见的辅助文字 |
| --- | --- |
| 关联研究快照 | 选择本次决策真正依据的当时研究版本；定稿后该版本不会被后续研究覆盖。 |
| 市场当前主要相信什么？ | 写当前价格隐含的主流预期及其依据；不要把自己的观点写在这里。 |
| 我的判断与市场的关键分歧 | 只写会实质影响价值或回报的分歧，并说明自己为何可能正确。 |
| 估值结论 | 写合理价值区间或明确的定性判断，并标明使用的方法；不强迫一个精确数字。 |
| 估值关键假设 | 写对结果最敏感的少数变量及取值依据；例：收入增速、利润率、折现率。 |
| 安全边际是否足够，为什么？ | 说明当前价格对估值偏差和不确定性留出了多少空间；不把“好公司”等同于“有安全边际”。 |
| 仓位上限、资金安排和分批原则 | 写与自身风险承受力一致的上限和执行原则；价格、日期提醒转到投资待办。 |
| 哪些事实说明判断错了？ | 写未来能被观察的证伪信号；例：核心客户留存率持续下降，而非只写“股价下跌”。 |
| 错了以后如何处理？ | 预先写明暂停加仓、重新评估、减仓或退出的触发原则；避免临场决定。 |
| 本次明确不能做什么 | 只记录本次最需要约束的行为；例：不追涨、不超出仓位上限。 |
| 决定 | 选择这一时点的真实行动结论；“继续观察”和“放弃”也是有效决策。 |
| 决策日期 | 记录实际作出这次判断的日期，不是补录或最后编辑日期。 |
| 核心理由 | 用少数几句连起分歧、估值、安全边际和行动；不要复制整份公司研究。 |

## 6. 组件与数据边界

新增一个小型、无业务状态的字段引导组件，仅负责统一辅助文字的排版和语义。公司研究与投资决策分别保留自己的字段配置，避免建立过度通用的表单引擎。

引导组件通过 `Form.Item.extra` 挂载，由 Ant Design 生成字段关联和布局。提示文案是静态界面内容，不写入数据库，不进入研究快照、投资决策、PDF 导出或 API 请求。本次不改变任何字段的必填性、保存结构、定稿校验或只读规则。

## 7. 无障碍与响应式

- 辅助文字不仅靠颜色表达含义，完整语句本身可独立理解。
- 使用表单组件已有的语义关联，不使用仅鼠标悬停才可读的 tooltip。
- 提示换行时不覆盖输入框，不通过固定高度截断文字。
- 校验错误使用错误色，写作提示保持中性次要色，两者视觉和语义上均可区分。

## 8. 测试与验收

### 8.1 组件测试

- 公司研究所有可填写核心字段都渲染对应辅助文字。
- 投资决策所有可见字段，包括快照、下拉选择和日期，都渲染对应辅助文字。
- 输入已有内容后，辅助文字仍在 DOM 中且可见。
- 已定稿决策处于禁用状态时，辅助文字仍可见。
- 现有表单初始值、保存和定稿交互不受影响。

### 8.2 视觉验收

分别在桌面端和窄屏宽度检查公司研究与投资决策页：

- 辅助文字的层级弱于字段标签和用户输入，但对比度足够阅读。
- 页面不出现大面积高亮、重复图标或每项三行说明导致的“考试卷”观感。
- 较长提示、已填长文本和表单错误同时出现时不重叠、不裁切。
- 页面实际高度虽有增加，但卡片之间不额外增加无意义留白。

## 9. 不在本次范围

- AI 生成、改写或评价研究与决策内容。
- 自动根据用户文字推断是否“写对”。
- 增加字数门槛、完成率、评分或勋章。
- 通用模板编辑器或允许用户自定义提示文案。
- 修改数据库、API、研究快照或决策定稿逻辑。

# 人生工作台表达训练模块设计

日期：2026-09-30  
状态：用户已确认产品方向，待规格复核  
范围：生活补强第一版，仅实现表达训练样板

## 1. 背景与设计结论

生活补强未来可能覆盖健康、形象、人际、表达和组织能力，但第一版不同时建设五套系统。用户明确希望系统能够提醒自己，并按顺序攻克弱项；用户目前不知道各弱项的关键问题和训练动作，因此模块不能只是任务清单，也不能依靠复杂评分制造进展感。

第一版只处理表达能力，采用“固定课程骨架 + Codex 自适应指导 + 真实场景验证”。人生工作台负责当前阶段、训练提醒、Codex 结果、下一步动作、阶段解锁和代表成果；独立 Codex 任务负责音频工具调用、内容分析和结构化结果回写。现有年度目标、统一计划、提醒和人际关系继续复用，不建立第二套目标、任务、联系人或提醒系统。

第一版训练路线收缩为三阶段：

1. 结构化表达。
2. 抖音视频实战。
3. 朋友对话实战。

说服能力暂不进入第一版。以后出现产品合作、报价、邀请或谈判等真实需求时，再以具体场景单独设计。

## 2. 产品原则

1. 一次只显示和推进一个阶段，完整路线仅供查看。
2. 默认每周四次 15 分钟微训练，加一次阶段作品；不设计连续打卡奖励。
3. 训练前只要求用户写一句“希望听众记住什么”，不要求填写完整提纲。
4. 日常训练不触发解锁。只有用户主动发起阶段验证时，Codex 才给出“通过”或“继续训练”的建议。
5. Codex 每次只返回最多两条具体依据和一个下一步训练动作，不生成综合评分、雷达图、等级或长篇建议。
6. Codex 的判断必须区分工具事实、派生测量和模型判断；模型判断必须引用逐字稿或用户反馈中的证据。
7. 用户拥有最终解锁权。Codex 不能自动更新阶段，也不能自动把第三方信息写入联系人档案。

## 3. 页面与日常流程

启用现有导航中的“生活补强”，第一版进入 `/life`，直接显示表达训练当前攻克台。页面包含六个区域：

- 当前阶段：阶段名称、目标和路线位置。
- 本周安排：每周四次微训练、一次阶段作品及下一次提醒。
- 今日训练：话题、可选事实卡、“希望听众记住什么”和“复制任务给 Codex”。
- 最近结果：通过/继续训练、最多两条依据、一个下一步动作。
- 阶段验证：用户主动发起；Codex 返回结果后由用户确认。
- 代表成果：每阶段只保留必要作品引用和简短总结，不把所有练习做成内容仓库。

默认训练话题由系统或 Codex 推荐，用户可以换题、使用自己的真实话题，或在不知道练什么时与 Codex 讨论。热点训练分为“提供事实卡的表达训练”和后续可选的“即兴观点”；第一阶段默认提供事实卡，避免把知识不足误判为表达问题。金融热点必须附来源并注明训练针对表达结构，不构成投资建议。

提醒复用 `plans` 的 `life` 领域与现有站内提醒。系统只建立一条周期训练计划，不为每次练习生成独立任务。未完成时不连续催促；周末若阶段作品仍未完成，只额外提醒一次。连续两周训练不足时，提示用户决定降低频次、调整时间、暂停或继续，不自动修改目标和阶段。

## 4. 三阶段训练与评估

### 4.1 结构化表达

目标是在三分钟内让听众能够复述一个核心观点和两条主要理由。训练内容包括结论前置、观点—理由—例子、删减跑题内容和同题重录。

用户把录音交给独立 Codex 任务。工具先完成转写、时间戳/VAD 和确定性规则分析；AI 再从逐字稿中独立提取核心观点、理由与例子，并与用户事先填写的“希望听众记住什么”对照。

语速、停顿、重复和口头禅不得由模型凭感觉判断。语速由时长与有效中文字数计算；停顿由时间戳或 VAD 计算；重复和口头禅由可审计规则标出原文。AI 只负责解释这些现象是否可能影响当前表达，并引用证据。

### 4.2 抖音视频实战

目标是把结构化表达迁移到真实发布场景。发布前仍填写一句“希望观众记住什么”；发布后向 Codex 提供作品材料、后台截图和有代表性的评论。

当前 Codex 模型不能直接接收完整视频。分析工作流必须明确采用工具拆解：提取音轨、生成逐字稿，必要时抽取有限关键帧，再结合用户提供的抖音数据和评论。第一版不自动评价眼神、动作、情绪或完整镜头表现。

评估只回答三个问题：观众是否可能接收到原定核心；内容结构或语言表达哪里阻碍理解；抖音评论和后台结果暴露了什么问题。播放量、点赞量和完播率受选题、标题、账号权重与平台分发影响，不能直接等同表达能力。页面必须区分“表达问题”和“分发/选题问题”。

### 4.3 朋友对话实战

目标是减少单方面输出，通过追问和复述帮助对方展开，并正确理解对方。具体联系对象和提醒复用现有人际关系模块。

支持两种复盘输入：

- 有录音：只有在对方明确同意后，才把录音交给 Codex；工具可分析发言轮次、连续发言时长、追问、复述确认和话题转回自己的位置。
- 无录音：聊天后由用户口述或填写“原本想了解什么、对方说了什么、哪里卡住或说得过多”。

Codex 输出一个主要问题、一句当时可使用的替代表达和一个下次动作。与朋友近况有关的摘要，经用户单独确认后写入 `contact_interactions`；训练改进写入表达训练记录。两类数据不得自动混写。

## 5. Codex 回写契约

人生工作台与独立 Codex 任务共享一个最小结果契约：

```json
{
  "task_id": "uuid",
  "stage": "structured | video | conversation",
  "record_type": "practice | stage_validation",
  "intended_message": "用户希望听众记住的一句话",
  "decision": "pass | continue",
  "evidence": [
    { "summary": "依据说明", "quote": "原文或反馈证据", "time_range": "可选" }
  ],
  "next_action": "下一次只练的一个动作",
  "artifact_ref": "可选的本地报告ID、作品链接或文件哈希",
  "source_type": "codex",
  "review_status": "pending"
}
```

`evidence` 最多两项。服务端必须拒绝 Codex 来源直接写成 `approved`。用户在网页确认后，结果才成为正式记录；阶段验证为 `pass` 时，这一次确认同时表示接受结果并解锁下一阶段，不再要求第二次确认。

目标体验是 Codex 通过受控接口写入待确认结果。若服务身份、令牌轮换和权限隔离尚未达到安全要求，第一版可以使用同一契约生成 JSON，由网页预览并确认导入；不得把 Supabase service role key 暴露给浏览器或写入报告。直接写回与 JSON 导入必须使用同一校验逻辑，避免形成两套行为。

原始音频和完整逐字稿必须全程只在本机处理，不允许上传第三方云转写服务。本地分析较慢、失败或准确度不足时，只能提示重试、调整本地模型或参数，或由用户人工修正逐字稿；系统不得静默切换到云端。

## 6. 数据设计

新增两类最小数据，不扩展成通用课程平台：

### `life_skill_progress`

- `id`、`user_id`。
- `skill_key`：第一版固定为 `expression`。
- `current_stage`：`structured`、`video`、`conversation`、`completed`。
- `next_action`。
- `active_plan_id`：可选关联统一计划。
- `created_at`、`updated_at`。

每个用户和 `skill_key` 唯一。训练频次、提醒时间和计划状态继续保存在 `plans`/`reminders`，不在这里重复保存。

### `life_training_records`

- `id`、`user_id`、`skill_key`、`stage`。
- `record_type`：`practice` 或 `stage_validation`。
- `topic`、`intended_message`。
- `decision`：`pending`、`pass`、`continue`。
- `evidence`：最多两项的 JSONB。
- `next_action`。
- `artifact_ref`：作品链接、本地报告 ID 或文件哈希；不保存原始音频。
- `contact_id`：对话阶段可选关联现有联系人。
- `source_type`、`source_ref`、`review_status`。
- `created_at`、`updated_at`、`confirmed_at`。

表启用 RLS，只允许用户读取和确认自己的记录。Codex 写入路径只能创建 `pending` 记录，不能更新用户阶段、联系人或计划。

## 7. 组件与边界

- `LifePage`：加载进度、当前计划、最近已确认结果和待确认结果。
- `CurrentStageCard`：只展示当前阶段目标与路线位置。
- `WeeklyTrainingCard`：读取统一计划与提醒，不维护第二套频次状态。
- `TodayPracticeCard`：选择话题、填写 intended message、生成任务编号和 Codex 任务文本。
- `CodexResultReview`：预览待确认结果，支持确认、拒绝和请求重新分析。
- `StageValidationCard`：发起阶段验证；用户确认 `pass` 后推进阶段。
- `RepresentativeOutcome`：每阶段展示必要成果引用与总结。

页面不包含音频上传、完整逐字稿编辑、复杂分析图表或模型设置。音频工具链与完整报告属于独立 Codex 任务。

## 8. 数据流

1. 用户在 `/life` 打开当前阶段训练，选择题目并填写 intended message。
2. 页面创建训练任务 ID，并生成可复制给 Codex 的任务文本。
3. 用户在独立 Codex 任务提交音频、视频材料或对话复盘。
4. Codex 调用转写、VAD、规则分析和内容分析工具，生成符合契约的结果。
5. Codex 通过受控接口写入待确认记录；安全条件不足时生成 JSON 供用户导入。
6. 网页显示待确认结果。用户确认后记录转为正式状态，并把 `next_action` 写入当前进度。
7. 若记录属于阶段验证且 decision 为 `pass`，同一次确认由服务端以事务方式推进阶段；不增加第二个确认步骤。
8. 对话记录中的联系人摘要必须走独立确认动作，再写入现有往来历史。

## 9. 异常与安全处理

- 转写失败或音频不清：不生成评价，返回需要重录或补充材料；不能用不完整逐字稿强行判断。
- Codex 结果缺字段、证据超过两项或枚举非法：服务端拒绝写入并保留错误信息，不创建半成品正式记录。
- 重复回写：使用 `task_id + source_ref` 幂等，重复请求返回已有待确认记录。
- 用户拒绝结果：记录保留为 `rejected` 供审计，不改变阶段和下一步动作。
- 阶段写入冲突：服务端检查当前阶段与验证记录阶段一致，避免旧结果解锁新阶段。
- 原始音频和完整逐字稿：只存在于用户本机，不上传 Supabase 或任何第三方云服务。对话录音必须先确认对方同意。
- 本地转写不可用：明确显示失败原因和可选的本地修复动作，不提供自动云端降级。
- 抖音材料：页面只保存用户主动提供的作品链接、必要摘要和反馈，不抓取私人数据。
- Codex 不可用：页面仍可查看路线、提醒和历史；用户可以稍后继续，不阻塞现有计划和人际模块。

## 10. 验收标准

1. `/life` 只显示表达训练当前阶段，不出现健康、形象、组织等空模块。
2. 用户能建立或关联一条 `life` 领域周期计划，并在工作台收到既有提醒。
3. 用户能生成训练任务，填写一句 intended message，并看到唯一任务 ID。
4. 待确认 Codex 结果最多包含两条依据和一个下一步动作；页面不显示综合评分。
5. 非人工来源无法绕过 `pending` 直接成为正式结果。
6. 日常练习不会自动解锁；只有阶段验证为 `pass` 且用户确认后才能推进阶段。
7. 视频页面明确说明分析基于音轨、逐字稿、有限关键帧和用户提供的抖音反馈，不宣称直接理解完整视频。
8. 对话阶段支持经同意的录音分析和无录音复盘；联系人摘要与训练结果分别确认、分别写入。
9. 原始音频不进入人生工作台数据库或对象存储。
10. 计划、人际关系、年度目标和提醒的现有行为不受影响。
11. 在断网环境或未配置云 API 密钥时，本地转写和确定性分析仍可工作；任何功能不得把音频发送到外部服务。

## 11. 明确不做

- 健康、形象、组织能力模块。
- 说服训练。
- 网页直接处理或保存音频、视频。
- 自动评价眼神、肢体、情绪或“感染力”。
- 综合分数、雷达图、等级、徽章和连续打卡。
- 根据播放量自动判断表达能力。
- 未经用户确认自动解锁阶段、修改计划或写入联系人记录。

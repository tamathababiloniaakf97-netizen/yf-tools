# 周期起点、进度计算与钟摆提示设计

## 背景与目标

现有“周期观察”支持手工维护周期阶段、判断、证据、指标和复核历史，但缺少一个直观的价格与时间锚点。用户希望在确认某个周期已经启动后，补录可修改的启动日期与启动价格，并在复核时手动输入最新价格，由系统计算累计涨跌幅和已经运行的时间。

本功能是轻量的周期位置记录器，不是行情系统、顶底预测工具或自动交易系统。价格变化和运行时间只提供客观背景，当前阶段仍由用户根据提示词手动判断。

## 核心原则

页面固定显示短提醒：

> 周期只用于判断环境，不用于预测顶底；通过分批买卖降低误判与踏空风险。

系统不自动获取行情，不根据涨跌幅或运行时间自动判断阶段，不输出买卖或仓位建议。周期起点允许事后补录和修改，因为用户可能在周期运行较长时间后才确认其起点。

## 当前周期锚点

每个周期观察主题只保留一个当前周期起点：

- `cycle_started_on`：周期启动日期，由用户手动输入，可为空；
- `cycle_start_price`：周期启动价格，由用户手动输入，可为空且必须大于零；
- `latest_price`：本次复核时的最新价格，由用户手动输入，可为空且必须大于零；
- `latest_price_on`：最新价格对应日期；填写最新价格时默认当天，但允许修改。

没有明确价格的周期可以不填写任何价格字段，仍可正常使用原有阶段、判断、指标和复核功能。空值不得转换为零，也不得显示虚假的 `0%` 或“运行 0 天”。

## 计算规则

只有启动价格和最新价格都存在且大于零时才计算累计涨跌幅：

```text
累计涨跌幅 =（最新价格 - 启动价格）÷ 启动价格 × 100%
```

只有启动日期和最新价格日期都存在时才计算运行时间：

```text
运行天数 = 最新价格日期 - 启动日期
```

日期按自然日计算，不受时区中的具体时刻影响。如果最新价格日期早于启动日期，拒绝保存并提示修正。界面以“X 天”作为准确结果，并在时间较长时辅助显示约 X 个月或 X 年，但不以月份近似值替代天数。

计算在领域纯函数中完成，界面和 API 共用相同规则。数据库同时保存输入值和复核当时的计算结果，确保历史记录不会因为后来修改当前周期起点而改变。

## 钟摆阶段与提示词

阶段由用户手动选择，第一版提供六个通俗选项：

1. **启动**：是否出现低位企稳、基本面改善或新的驱动力？
2. **扩张**：上涨是否由基本面、资金和参与者共同推动？
3. **亢奋**：市场是否开始忽略风险、估值和反面证据？
4. **转弱**：价格仍高，但趋势、基本面或情绪是否开始减弱？
5. **下跌**：负反馈是否形成，悲观是否仍在扩散？
6. **修复**：极端悲观是否缓解，价格和基本面是否开始企稳？

阶段选项借鉴霍华德·马克斯关于市场心理在乐观与悲观、低估与高估之间摆动的思想，但不宣称六个阶段是原理论的正式分类。提示词只帮助用户组织观察，不参与自动评分或自动判定。

数据库继续以普通文本保存阶段，以兼容旧记录和未来调整。界面优先显示六个选项，同时保留自定义阶段的兼容能力。

## 页面与交互

在现有 `/investment/cycles` 页面当前判断区域上方增加“周期进度”区：

- 第一行输入启动日期、启动价格、最新价格和最新价格日期；
- 第二行展示自动计算的累计涨跌幅和运行时间；
- 缺少计算条件时显示“尚未填写”，而不是数字零；
- 当前阶段选择器下方展示对应的思考提示词；
- 固定短提醒放在页面标题下方或当前判断卡片顶部，始终可见但不使用强警告样式。

最新价格日期在用户首次填写最新价格时自动带入当天日期。编辑已有数据时，不因打开页面或修改其他字段而自动覆盖原日期。

修改启动日期或启动价格后保存时，如果该主题已经存在历史复核，显示二次确认：

> 修改周期起点后，当前涨跌幅和运行时间会重新计算；已有历史复核不会改变。

用户确认后才保存。没有历史复核时无需额外确认。

## 保存与历史

当前周期档案保存当前有效的启动日期、启动价格、最新价格和最新价格日期。每次“保存本次复核”时，复核快照额外保存：

- 当时采用的启动日期与启动价格；
- 本次最新价格与价格日期；
- 当时计算出的累计涨跌幅与运行天数；
- 阶段、置信度、判断、证据、未知项和指标快照。

后续修改当前周期起点不会回写旧快照。历史列表在存在价格数据时显示“阶段 · 涨跌幅 · 已运行天数”；无价格数据时继续只显示阶段与判断。

## 数据迁移与兼容

对 `market_cycle_profiles` 和 `market_cycle_reviews` 做增量字段扩展。所有新字段允许为空，现有周期档案和历史复核升级后保持可用。迁移不修改现有阶段、判断、指标或提醒规则。

API 对价格进行有限数校验并要求大于零，对日期使用 `YYYY-MM-DD` 格式校验。最新价格与价格日期必须成对出现；周期启动日期和启动价格允许独立填写，以支持用户先记录已知信息，但只有条件完整时才计算结果。

## 第一版边界

第一版不包含：

- 自动行情获取、标的关联或价格同步；
- 多个并行周期起点或完整周期区间数据库；
- 根据价格、涨幅、时间或指标自动判定阶段；
- 顶部、底部、买卖点或仓位预测；
- 周期之间的历史收益比较、图表或回测；
- 因阶段变化自动重置周期起点。

## 测试与验收

至少覆盖：

- 起点与最新价格完整时正确计算正负涨跌幅；
- 日期完整时正确计算自然日运行天数；
- 任一计算条件缺失时返回空结果而非零；
- 非正价格、无效日期和最新价格日期早于启动日期时拒绝保存；
- 首次输入最新价格时日期默认当天，编辑时不覆盖已有日期；
- 六个阶段展示正确提示词，阶段仍由用户选择；
- 修改已有周期锚点时触发确认，历史复核保持不变；
- 新复核快照固化当时的锚点、价格和计算结果；
- 没有价格的周期仍能完成原有复核；
- 旧档案、旧复核、指标提醒和到期提醒保持可用；
- 相关测试、类型检查、lint 和生产构建通过。

## 成功标准

用户可以在发现周期启动后补录并随时修正起点，在每次复核时手动输入最新价格，立即看到累计涨跌幅和运行时间；系统通过简短提示词帮助用户判断所处阶段，同时明确阻止把周期分析误解为精确顶底预测或直接买卖信号。

# 持仓价格同步修复设计

## 问题与已验证事实

持仓页“一键更新收盘价”当前使用东方财富和 Binance。在当前运行环境中，东方财富 `push2` 请求连接失败，Binance 返回 451，Yahoo Finance 返回 403。现有同步接口又把“未获得价格”当作非错误，导致前端可能显示“已更新 0 个”而不说明原因。

开发前已从本机实际验证新数据源：

- 腾讯行情返回美股 SPY 价格 `765.61`。
- 腾讯行情返回港股腾讯控股价格 `432.000`。
- 腾讯行情返回 A 股贵州茅台价格 `1235.58`。
- Coinbase 返回 BTC-USD 价格 `83978.005`。

上述数值只是可用性验证时的快照，不写入程序或测试预期。

## 数据源与代码转换

股票类标的统一使用腾讯行情 `https://qt.gtimg.cn/q=<symbol>`：

- 美股 `stock_us`：前缀 `us`，例如 `SPY` 转为 `usSPY`。
- 港股 `stock_hk`：移除非数字字符并补足五位，前缀 `hk`，例如 `700` 转为 `hk00700`。
- A 股 `stock_a`：以 6 或 9 开头使用 `sh`，其他使用 `sz`，例如 `600519` 转为 `sh600519`。

加密货币 `crypto` 使用 Coinbase 现货价格接口 `https://api.coinbase.com/v2/prices/<pair>/spot`。代码若已包含 `-`则保留交易对，否则补为 `<code>-USD`。

本次不保留东方财富、Binance 或 Yahoo Finance 作为自动备用源，避免已知不可用请求拉长刷新时间并混淆错误。手动输入现价继续作为用户可控的兜底。

## 同步与错误语义

每次点击都实时请求，不使用 Next.js 五分钟缓存。每个标的独立处理，一个失败不阻止其他标的更新。

同步结果明确分为：

- 获价和数据库保存均成功：返回价格、数据源和更新日期，计入成功数。
- 代码或类型不支持、上游请求失败、响应无价格：返回可读失败原因，计入失败数。
- 数据库保存失败：即使已取得价格也不计成功，必须向前端报错。

前端仅将后端确认保存成功的价格写入当前页面和 `localStorage`。提示文案为“成功更新 X 个，失败 Y 个”；失败时列出标的代码和简短原因。全部失败时不显示成功提示。

## 边界与验收

- 不改动交易记录、成本计算、持仓计算和手动改价。
- 无需新增 API 密钥或付费账户。
- 美股、港股、沪深 A 股和加密货币代码均有转换和解析测试。
- 测试覆盖上游失败、无价格、数据库保存失败、部分成功和全部失败。
- 实际点击“一键更新收盘价”后，页面现价、市值、盈亏和更新日期一并重算，刷新页面后仍保留已保存价格。

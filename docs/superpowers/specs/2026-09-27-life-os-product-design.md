# 人生工作台产品与界面设计说明 v0.1

日期：2026-09-27  
状态：产品范围已确认，待进入开发计划  
产品名称：人生工作台

## 1. 背景与改造结论

现有项目名为“远峯投资策略工作台”，目前包含成本记录、AI 策略构建、策略执行、资源/关于和登录等页面。此次改造不是在原投资工作台上继续堆叠模块，而是将产品整体重新定位为“人生工作台”。旧系统中仅保留并复用现有成本记录/持仓页面，包括交易录入、持仓计算、收益指标、净值曲线、价格同步和相关 Supabase 数据。旧 AI 策略构建、策略执行、资源/关于等页面不进入新导航，也不作为新产品能力继续开发。

为降低迁移风险，第一阶段只从新导航和用户路径中停用旧页面，不立即物理删除代码、接口和数据库表。新系统稳定并完成数据核对后，再单独决定是否清理旧实现。

## 2. 产品目标

人生工作台用于帮助用户把重要目标转化为可执行计划，并通过提醒、验证和复盘形成闭环。核心链路是：

目标 → 项目 → 计划 → 提醒 → 执行 → 结果 → 复盘

产品不追求记录全部信息，也不追求复杂评分和数据大屏。首页优先回答“现在最需要处理什么”，计划系统优先解决“想得多、容易忘、长期不推进”，投资模块优先解决“已有判断缺少持续验证和复盘”。

## 3. 第一阶段范围

第一阶段必须完成以下内容：

1. 将产品名称、整体框架和左侧导航改为“人生工作台”。
2. 工作台首页。
3. 统一计划管理。
4. 提醒基础能力。
5. 投资概览。
6. 复用现有持仓页面。
7. 投资观察列表。
8. 公司研究。
9. 投资待办。
10. 投资复盘。
11. 投资方法论。
12. 年度目标基础功能。

后续阶段包括生活补强、全局复盘和投资观点库。第一阶段保留入口或产品边界说明，但不实现完整业务能力。

明确不做：自动新闻抓取、全市场行情系统、AI 自动投资建议、自动交易、复杂数据中心、社交评分和游戏化积分。

## 4. 全局信息架构

左侧一级导航固定为：

- 工作台首页
- 计划管理
- 投资（可展开）
- 年度目标
- 生活补强（后续）
- 全局复盘（后续）

投资模块内部导航为：

- 投资概览
- 持仓（复用现有页面）
- 观察列表
- 公司研究
- 投资待办
- 投资复盘
- 方法论
- 观点库（后续）

旧“AI 策略构建”和“策略执行”不出现在新导航中。“投资待办”不是第二套任务系统，而是统一计划数据中所属领域为“投资”的筛选视图。“投资复盘”针对公司、假设和具体投资决策；后续“全局复盘”用于跨投资、目标和生活领域的行为复盘，两者职责不同。

## 5. 页面设计

### 5.1 工作台首页

首页是行动入口，不是数据中心。默认按周组织，不要求用户每天制定计划。

首页展示：本周重点（最多三项）、等待处理的验证或决策、正在推进的项目、本周完成事项。系统可以提示长期未推进或已延期计划，但不能自动替用户改变状态。

### 5.2 计划管理

所有领域共用同一套计划实体。计划至少包含标题、类型、所属领域、关联项目、开始时间、截止时间、提醒规则、状态、备注、复盘记录和数据来源。

计划类型第一阶段支持验证、投研、交易、生活、行动和决策。状态统一为未开始、进行中、完成、暂停、延期和取消。页面提供本周重点、全部计划列表和基本筛选；看板属于同一数据的展示方式。

提醒第一阶段支持到期提醒、周期提醒和未完成提醒。通知渠道需要在实施前结合现有部署环境确认，不能在未验证可靠性的情况下承诺微信或手机推送。

### 5.3 投资概览

投资概览只展示能够触发行动或帮助判断风险的信息，不复制完整持仓页。顶部保留总资产、总盈亏、策略收益率和当前主要风险。核心区域依次为：需要用户处理的事项、组合暴露、主要持仓研究状态、观察列表触发和最近判断/复盘。

资产和收益数据直接读取现有持仓系统，不建立第二套账户数据。概览中的风险提示属于规则提示，不等同于投资建议，也不能自动触发交易。

### 5.4 持仓

直接复用现有 `/cost` 页面及其数据和计算逻辑，不重新开发页面。新系统只负责将该页面接入“人生工作台 → 投资 → 持仓”导航，并允许投资概览、公司研究等页面跳转到它。

第一阶段不主动修改现有收益计算、交易流水、期权收入、价格同步和净值图逻辑。现有数据准确性问题应作为独立核对任务处理，避免在界面改造中暗中改变财务口径。

### 5.5 观察列表

观察列表与持仓共享公司/资产主记录，但状态不同。每个观察标的至少包含关注原因、进入条件、当前状态、下次检查时间和关联研究。支持接近条件、等待验证、研究中、暂缓和移除等状态。

观察条件的第一阶段实现以人工设置和人工确认优先。即使后续由自动化工具写入价格或事件，也只能生成待确认事项，不能自动形成买卖结论。

### 5.6 公司研究

公司研究是投资模块的核心页面。页面内部标签为研究概览、假设与验证、证据记录、决策与复盘、相关资料。

研究概览包含投资逻辑、当前判断、核心假设和主要风险/失效条件。假设必须可被证据支持或挑战；证据必须关联公司和可选假设，并记录来源、日期、影响方向和原文链接。当前判断必须保留更新时间和来源，避免长期未更新的结论被误认为最新判断。

### 5.7 投资待办

投资待办读取统一计划系统中的投资领域数据，支持按验证、投研和交易类型筛选。交易计划只用于记录条件和提醒，系统不自动交易。

### 5.8 投资复盘

复盘记录至少回答：当初做了什么决定、依据是什么、当时已知什么、后来发生什么、判断中哪些正确或错误、下一次如何改进。评价时区分结果和决策过程，避免只根据盈亏倒推决策质量。

### 5.9 方法论

方法论保存可重复使用的原则、检查清单和纪律，第一阶段按买入前检查、持仓管理纪律和复盘规则组织。方法论不是知识文章库，其内容应能直接用于计划、研究或复盘时的检查。

### 5.10 年度目标

年度目标采用“年度目标 → 季度项目 → 行动计划”三级结构。页面显示目标进度、当前季度项目、下一步行动和需要调整的停滞项。进度优先由关联计划和项目状态汇总，不要求用户维护复杂评分。

### 5.11 后续模块

生活补强围绕健康、形象、人际、表达和组织能力，统一使用“目标—行动—成果—复盘”，不设计复杂评分。全局复盘跨领域总结执行问题。观点库接收人工、Codex 和采集工具写入的外部投资观点，并可关联公司、假设和证据；它不是新闻中心。

## 6. 数据模型原则

第一阶段建议采用以下核心实体：

- `profiles`：用户资料与偏好。
- `goals`：年度目标。
- `projects`：季度或阶段项目。
- `plans`：统一计划。
- `reminders`：提醒规则和发送状态。
- `assets`：公司、证券或其他资产主记录。
- `watchlist_items`：观察状态和进入条件。
- `research_profiles`：公司研究概览与当前判断。
- `research_hypotheses`：研究假设及验证状态。
- `evidence_records`：证据、来源和影响方向。
- `investment_decisions`：买入、卖出、持有或未行动等决策。
- `investment_reviews`：决策复盘与改进规则。
- `methodology_items`：方法论和检查项。

现有持仓、标的、交易、价格和净值相关表继续使用。新表通过用户 ID 和资产 ID 与现有数据关联，不复制交易和持仓结果。

## 7. 人工、Codex 与自动化写入

核心业务表从第一阶段开始保留统一来源和审计字段，至少包括：

- `source_type`：`manual`、`codex`、`automation`、`system`。
- `source_ref`：来源链接、任务标识或外部记录标识。
- `created_by`：写入用户或服务身份。
- `created_at`、`updated_at`。
- `review_status`：需要人工确认的数据使用 `pending`、`approved`、`rejected`。

人工输入通过页面表单写入。Codex 后续通过受控 API 或服务端工具写入。自动采集内容先进入待确认状态，再由用户批准成为正式证据或计划。浏览器端不得使用 Supabase secret key；自动化写入必须通过服务端身份、最小权限和可追踪日志完成。

## 8. 迁移与路由策略

建议迁移顺序：

1. 新建人生工作台应用框架与导航。
2. 保持登录和 Supabase 会话机制。
3. 将 `/cost` 作为投资持仓入口接入新导航。
4. 新建首页、计划和年度目标基础页面及数据表。
5. 新建投资概览、观察列表和公司研究。
6. 新建投资待办、复盘和方法论。
7. 从导航移除 `/strategy`、`/execution`、`/about`，但暂不删除实现。
8. 完成数据核对和稳定期后，再决定旧代码清理。

## 9. 主要风险

第一，现有持仓截图中部分仓位比例合计可能超过 100%，现金也出现负值。可能是保证金、期权或统计口径导致，也可能是计算问题。在投资概览复用数据前必须明确口径，否则风险提示会产生误导。

第二，提醒可靠性不仅是页面功能，还依赖调度服务和通知渠道。第一阶段应先验证站内提醒或邮件中的一种完整链路，不应同时承诺多个渠道。

第三，自动化写入如果直接进入正式研究记录，会混淆事实、外部观点和系统推断。所有采集内容必须保留来源并经过人工确认。

第四，旧页面直接删除可能误伤仍被持仓页引用的类型、接口或工具函数，因此采用先停用后清理。

第五，模块较多，若第一阶段同时追求全部细节，容易再次形成“规划很多但难以上线”的情况。实现应以首页、统一计划、提醒、年度目标、持仓复用和最小投资研究闭环为首个可用版本，其余页面允许先提供基础增删改查。

## 10. 第一阶段验收标准

用户登录后能看到人生工作台新导航；能够建立年度目标、项目和计划，并把最多三项计划设为本周重点；到期、周期和未完成提醒能够可靠产生；投资概览能够读取现有持仓数据并展示待处理事项；现有持仓页面及历史数据保持可用；能够添加观察标的、研究假设、证据、投资决策和复盘；投资待办与全局计划使用同一数据；所有新增记录能够区分人工、Codex、自动化和系统来源；旧策略、执行和关于页面不再出现在新导航中。

## 11. UI 原型结论

已确认采用深色左侧导航、浅色内容区和投资模块展开式二级导航。首页按周组织，限制三项重点。投资页面以行动和判断为核心，完整账户统计留在现有持仓页面。当前原型用于确认信息架构和页面内容层级，不代表最终视觉细节或最终数据值。

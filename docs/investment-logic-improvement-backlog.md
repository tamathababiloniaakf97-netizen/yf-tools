# 投资模块逻辑改进清单

更新日期：2026-10-01

本清单记录投资模块完整流程审查中发现、但不适合在“先使用、再修缮”阶段一次性改造的问题。原则是先修正会误导判断或导致遗漏的缺陷，再补数据关联，最后改善导航与表达。

## 已优先处理

- [x] 投资概览主要风险不再只检查单一持仓集中度。负现金和融资敞口优先提示，其次检查股票敞口超过 100%，最后检查最大单一持仓。
- [x] 投资概览加入“今日需要关注”，汇总到期、逾期和长期沉寂的观察事项与投资待办。
- [x] 观察列表允许低门槛记录一般关注事项，并支持复核、延后提醒和转为待办。

## P1：连续使用阶段优先观察

- [ ] 统一投资概览“今日需要关注”和顶部铃铛的投资提醒来源。当前铃铛只包含有明确日期的投资待办，不包含沉寂待办和观察事项。
- [ ] 明确三种“验证”信息的边界：观察列表状态表达整体阶段；公司研究假设表达待验证判断；投资待办表达下一步验证动作。
- [ ] 降低投资待办分类摩擦：保留筛选能力，但新建时提供可靠默认值，不要求用户先判断分类才能快速记录。
- [ ] 观察实际使用两周后评估沉寂阈值。当前无日期待办为 7 天、无日期观察事项为 14 天；避免在没有使用数据前增加复杂的个人化规则。

## P2：建立关键数据关联

- [ ] 为适合的观察事项增加“开始公司研究”，避免在观察列表和公司研究中重复输入标的名称。
- [ ] 建立投资决策与实际交易之间的可选关联，记录计划是否真正执行以及实际价格、数量和日期。
- [ ] 让投资复盘能够同时引用已定稿决策和一笔或一组真实交易，区分决策质量与执行质量。
- [ ] 逐步减少仅靠 `asset_name` 文本匹配的关系；对股票等已有标的优先使用稳定的 `ticker_id`，宏观指标和主题仍保留自由文本。

## P3：完成学习闭环

- [ ] 投资复盘提供“沉淀为方法论”的人工确认入口，不自动生成规则。
- [ ] 投资决策可选引用本次实际使用的方法论，以便后续判断规则是否有效。
- [ ] 评估公司研究内“投资决策”标签与全局“投资决策”入口的文案区分，例如将前者改为“该标的决策”。
- [ ] 等核心关联稳定后再决定是否调整侧边栏顺序；避免用换位置掩盖数据断链。

## 已知折中

- 没有日期的沉寂提醒目前依赖 `updated_at`，任何编辑都会重新开始计时。
- 第一版只有站内提醒，不包含 Windows、邮件、微信或手机推送。
- 投资待办是跨阶段行动队列，不是观察、研究和决策之间的固定流程步骤。
- 方法论当前仍是人工维护的规则库，不是自动约束交易的规则引擎。

# 人生工作台 MVP 启用清单

## 当前范围

本次保留原有 `/cost` 持仓页面及其计算、交易录入和行情更新流程。新增工作台首页、统一计划、本周重点、年度目标、投资概览、观察列表、公司研究、证据记录、投资待办、投资复盘、方法论和站内提醒。生活补强、全局复盘和观点库只保留产品方向，本阶段不存储虚假数据，也不开放入口。

## 数据库启用

在对应 Supabase 项目的 SQL Editor 中，按顺序执行：

1. `supabase/migrations/003_life_os_core.sql`
2. `supabase/migrations/004_investment_research.sql`
3. `supabase/migrations/005_investment_reviews.sql`
4. `supabase/migrations/006_life_os_table_grants.sql`
5. `supabase/migrations/007_goals_relationships.sql`
6. `supabase/migrations/008_relationship_history_birthdays.sql`

这些迁移只新增人生工作台表、字段、索引、触发器和 RLS 策略，不修改现有持仓、交易、标的和净值数据。执行前仍建议在 Supabase 做一次数据库备份。未执行迁移时，原持仓功能可继续使用，新页面会显示明确的未连接提示。

## 自动写入约束

计划、观察、证据、研究、复盘和方法论均保留 `source_type`、`source_ref`、`review_status`。人工写入默认确认；自动化写入必须带来源标识并默认待确认。当前只完成数据契约和服务端接口，尚未接入外部采集器、微信、邮件或手机推送。

迁移 007 为年度目标增加结果型、项目型、习惯型和方向型进展字段，并新增 `contacts`、`contact_interactions`、用户级 RLS、审计字段和联系记录同步触发器。自动化来源联系人默认待确认。

迁移 008 在原表上增加同学关系、公历/农历生日、闰月和生日提醒字段，并为往来历史增加类型。已有联系记录会默认为“联系或见面”，不会丢失。

## 验收重点

- 登录后左侧导航不再出现旧策略、执行和关于入口，持仓仍指向原 `/cost` 页面。
- 本周重点最多三项；计划可创建、更新状态、完成或删除。
- 投资待办只读取统一计划中 `domain=investment` 的记录，不复制任务。
- 观察列表、研究证据、投资复盘和方法论可以人工写入；自动化来源数据保持待确认。
- 顶部提醒只展示活动计划中的延期、当天到期、到时提醒和每周周期事项，使用 `Asia/Shanghai` 时区。
- 年度目标按类型展示真实进展；项目型和方向型不显示根据计划数量推导的百分比，14 天未推进提示检查，30 天未推进提示停滞。
- 人际关系支持家庭、朋友、同学、工作、专业人士和其他联系人，手工设置计划联系日期；顶部提醒和首页显示到期联系，但不根据最近联系时间自动推断提醒。
- 分别建立公历、农历和农历闰月生日，验证生日前 7 天和当天提醒，关闭生日提醒后不再出现。
- 对同一联系人连续记录联系或见面、送礼、收礼、请教和帮助；确认联系人详情按日期倒序显示全部历史，新记录不覆盖旧记录。
- 确认新往来只同步最近联系日期、我的下一步行动和计划联系日期，不覆盖家庭近况、工作近况和观察与相处提示。
- 使用家庭、工作和专业人士各一条记录验证联系人档案、往来历史、下一步行动和计划联系；确认另一个用户无法读取或修改这些记录。
- 用两个不同用户验证 RLS：用户只能读取和修改自己的新增记录。

## 已知边界

旧 `/strategy`、`/execution`、`/about` 文件仍在代码中以避免破坏性删除，但正常导航不可达。完整仓位计算审计、外部通知、观点采集、生活模块和全局复盘不属于当前 MVP。现有账户出现负现金或仓位比例异常时，应单独核对历史交易与计算口径，不在本次界面改造中静默更改结果。

人际关系模块不保存身份证号、精确住址、财务账户或医疗诊断，不提供亲密度、人脉价值或关系健康评分，也不自动发送消息。人生工作台只有在核心流程连续实际使用两周且没有数据丢失或阻断问题后，才达到 10 月可用版本标准。

## 回滚

前端可切回改造前提交。数据库回滚时，先导出 007–008 中的联系人、生日和往来历史数据，再删除 `contact_interactions`、`contacts` 及目标新增字段；003–006 的回滚仍不得删除或改写 `tickers`、`transactions`、价格和净值相关表。
